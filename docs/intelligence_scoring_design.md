# Intelligence Scoring Agent Design

## 1. Architecture Overview
The Intelligence Scoring Agent acts as the aggregation tier in the agentic pipeline. It consumes the standardized outputs generated by the Deep Scraper, Technographic, and Intent Signal Agents. By adhering to the `BaseAgent` abstract base class and executing fully asynchronously, it guarantees consistent logging, error handling, and `agent_runs` observability.

The Agent will extract required context, evaluate the data through a deterministic scoring policy, and persist an append-only `intelligence_scores` record.

## 2. Scoring Methodology
The scoring system will reuse the existing `DeterministicScoreRefreshPolicy` by importing it directly from the workflow foundation (`app.workflows.scoring_policy`). This minimizes modifications to stable, already-tested components.

**Key characteristics:**
- **Deterministic**: Given the same inputs, the score will always be exactly the same.
- **Explainable**: The output will include a `rationale` string explaining how the score was calculated.
- **No AI/LLM**: Avoids unpredictability, latency, and cost associated with generative models. 
- **Modular**: Component scores will be calculated independently and summed based on a configurable weighting formula.

## 3. Component Score Model
The total intelligence score (0-100) will be composed of four sub-scores:
1. **Fit Score (30%)**: Evaluates static data (industry, company size, contact seniority).
2. **Intent Score (35%)**: Evaluates temporal buying signals (funding, hiring, pricing page visits) with a time-decay factor (e.g., 90-day lookback).
3. **Technographic Score (25%)**: Evaluates the diversity and confidence of the detected tech stack.
4. **Engagement Score (10%)**: Evaluates completeness of the contact and company profile as a proxy for reachability.

## 4. Confidence Model
The final score will include a confidence bounded between `0.0` and `1.0`. The confidence grows as more high-quality evidence is found.
- Baseline confidence is established based on the presence of static company/contact fields.
- Additional confidence is awarded linearly based on the sum of technographic and intent signal confidences, capped at a maximum contribution.

## 5. Database Interactions
- **Read**: `Company`, `Contact` (optional), `Technology`, `IntentSignal`.
- **Write**: Appends a new `IntelligenceScore` record using `IntelligenceScoreService.create()`.
- **Write**: Integrates with `AgentRunService` implicitly through `BaseAgent` lifecycle hooks to record execution status.

## 6. Service Interactions
- **CompanyService**: Fetch company data.
- **ContactService**: Fetch contact data if `contact_id` is present in `AgentContext`.
- **TechnologyService**: Fetch all technologies associated with the `company_id`.
- **IntentSignalService**: Fetch all intent signals associated with the `company_id` and optionally `contact_id`.
- **IntelligenceScoreService**: Persist the final score.

## 7. Testing Strategy
- **Unit Tests**: Mock service dependencies to strictly test the agent's orchestration logic.
- **Policy Tests**: Test the deterministic scoring algorithm with various edge cases (empty technologies, expired intent signals, partial company data) to ensure bounds (0-100 score, 0.0-1.0 confidence) are strictly respected.
- **Integration Tests**: Verify end-to-end execution utilizing the temporary SQLite database to ensure the `intelligence_scores` record is properly appended and linked to the `agent_runs` table.

## 8. Risks and Edge Cases
- **Missing Data**: Companies with no technologies or intent signals should still receive a baseline Fit Score without causing ZeroDivisionErrors.
- **Time Decay Drift**: Intent scores decay over time. Testing must strictly mock the `scored_at` datetime to prevent flaky tests.
- **Transaction Safety**: The agent should rely on the `IntelligenceScoreService` to handle transaction commits via `session_scope()`.
- **Workflow Stability**: The agent will directly import and utilize the existing `DeterministicScoreRefreshPolicy` without moving or modifying it, preserving the stability of the workflow layer.
